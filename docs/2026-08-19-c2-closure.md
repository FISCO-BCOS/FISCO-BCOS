## P0 #1 修复：extraTransactionBytes 双形态判别 ✅

**问题根因**：`extraTransactionBytes` 在交易生命周期中换形态——txpool 阶段存签名预影像（`encodeForSign()`），密封后 `buildOpBlock`（SEV-8）覆写为 wire 形态（全签名信封）。读回解码器按预影像数学解析密封后的 wire 形态，把 v 读进 chainId 槽（chainId=1829838），双重包装后 v=3659712 → tx hash 不一致 → op-node 报 "invalid transaction v,r,s" 卡链。

**修复方案（读侧判别 + 无写入方改动 + 零迁移）**：

- Legacy：RLP 整数 0 编码为空字节串，secp256k1 r/s 永非零 → 空-空尾部唯一标识预影像；否则按 wire 形态拆 v
- Typed：按固定字段数判别（2930=8/1559=9/4844=10/7702=11），N+3=wire，N=预影像
- `reassembleWeb3RawTransaction` 同步双形态（legacy wire r/s 交叉核对；typed 项数判别后 verbatim）

**测试覆盖**：
- `ExtraTxBytesDualLayoutTest`（7 条用例：legacy preimage/wire/pre-155 + typed preimage/wire + 垃圾尾部 + hash 一致性）
- `New1 T12-T14`（tars 侧：wire hash canonical + typed wire + signature mismatch 抛异常）
- `EngineRpcTest` V4 过时断言更新（`9a6fee4ff` 接线 V4 后未同步，本次一并修复）
- E2E：C2 链发 fresh tx → `chainId=0xdf5d5, v=0x1bebce` ✓、RPC hash == client 计算 hash ✓、历史错误交易读回也正确 ✓、op-node 零 "invalid v" 错误 ✓

**单测结果**：
- bcos-tars-protocol：全绿（1 个预存无关失败 `createSaltEmptyValueAndGarbage`，stash 确认非本次引入）
- bcos-rpc：全绿（1 个预存失败 `jwtHttpRequestAuthTest`；V4 断言修复后 EngineRpcTest 全绿）
- run_all B3/B3a：卡在 `op-fork-base-allocs.json` 基础设施缺口（非本次改动造成）
